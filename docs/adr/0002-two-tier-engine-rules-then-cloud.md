# 检测引擎两级架构：规则初审 + OpenAI-compatible 云端二审（本地模型排除）

Status: proposed

检测分两级：初审为规则引擎（命中 AI 创作痕迹清单即扣分），规则分落入模糊带（20–80）时才调用云端 LLM（默认 DeepSeek V4 Flash，OpenAI-compatible 接口）二审。本地模型方案（transformers.js + 中文分类模型）经调研后排除：专用中文 AIGC 检测器 409MB 且无量化版，浏览器内不可行；可用的量化通用 BERT（82–103MB）非 AIGC 专用，且短文本检测准确率大幅衰减（句子级从 ~97% 跌至 ~58%）。纯规则方案准确率不足，纯云端方案成本不可控。此架构须接受：模糊带内回答正文会外发至配置的 LLM 服务商；需为该 API 域名申请主机权限；调用有成本与延迟（每页上限 20 次、并发 2、失败降级为纯规则兜底）。

**Considered Options**:

- **本地模型（transformers.js）**：隐私好、无调用成本，但模型体积与短文本准确率均不可接受（见上）。
- **纯规则引擎**：零成本零外发，但短文本规则命中率有限，准确率不足。
- **纯云端 LLM**：准确率最高，但每条回答都调用，成本与延迟不可控。

**Consequences**:

- 选项页需提供 base URL / API key / 模型名三项配置，key 存 `chrome.storage.local`（不随账号同步、掩码显示）。
- 二审结果以回答 ID 为键缓存，滚动回看不重复调用。
