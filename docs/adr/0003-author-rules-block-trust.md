# 作者级规则：屏蔽 / 信任（zhihu.com/people/<token> 为主键的本地硬规则）

Status: accepted

用户需要"固定屏蔽某个作者"（不在乎是否人工）与"始终信任某个作者"（不在乎是否 AI）。现有判定管线只认 `answerId`（卡片级），不存在作者概念。经 grill 逐轮确认设计：屏蔽为**纯本地隐藏**（不模拟点击知乎平台的原生屏蔽按钮），信任为**一轮不跑**（一审/二审/角标全部跳过），两个方向对称、同一数据结构；身份以 `zhihu.com/people/<token>` 为稳定主键，昵称仅用于显示；匿名回答无作者链接不可操作。规则存 `chrome.storage.local`（键 `authorRules`：`{ blocked: {token: {name, ts}}, trusted: {...} }`，两列表互斥），跨页面持久化。

**Considered Options**:

- **模拟知乎平台原生屏蔽按钮**：依赖平台内部机制、不可控，且平台屏蔽语义（双方互不可见）与"单方面隐藏该作者回答"不同，排除。
- **纯本地隐藏 + 占位条**：不依赖平台，占位条可恢复（[查看] 临时展开正文 / [取消屏蔽]），选定。
- **信任走正常管线再置顶**：仍产生提取与判定调用，违背"一轮不跑"语义，排除。

**Consequences**:

- **优先级**：作者级规则 > 卡片覆盖 > 引擎判定。规则检查位于文本提取之前，屏蔽/信任卡均不产生提取与判定调用。
- **即时生效**：`storage.onChanged` 驱动重扫，规则变化应用到全页该作者全部卡片（含已分析、含跨页面——选项页操作对已打开页面实时生效）。
- **竞态防护**：渲染时刻 `applyAuthorRuleIfAny` 守卫——规则变化时卡片若正处于云端二审管道中（in-flight），旧管道完成后仍会执行 render，若不在渲染前再查一次规则，会把新渲染的占位条/小签清掉并显示旧判定（实测复现并修复）。
- **渐进渲染免疫**：规则应用后的卡片不随正文变化重分析（`ruleApplied` 守卫），知乎在卡片内追加操作栏/热评等节点不重建规则 UI（实测 12s 窗口内 0 次 zys 节点增删）。
- **管理入口**：角标面板「屏蔽该作者 / 信任该作者」（跳过卡面板同样可用；匿名卡不显示）+ 选项页「作者管理」section（按主页链接添加/移除，非法格式拦截；链接添加的作者昵称由页面分析时自动从 DOM 补全）。
- **已知边界**：首页折叠预览卡（`is-collapsed`）无 `.AuthorInfo`/people 链接，作者不可识别 → 不参与作者规则；展开「阅读全文」渲染完整作者信息后自动适用（正文变化重分析路径）。符合"无稳定身份不可操作"语义。
- **自己回答的保护**：暂缓（需调研知乎 API 如何标识当前用户身份，进 backlog）。
