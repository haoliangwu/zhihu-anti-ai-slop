# 知乎照妖镜 — P2 Spec

> Status: ready-for-agent · 关联: `.scratch/mvp/spec.md`（MVP，已交付）、`CONTEXT.md`、ADR-0001/0002
> 范围：MVP 之外的第二批能力，均为"明确不做"清单与词汇表"后续迭代"中的项目。

## 1. 背景

MVP（标记/理由/覆盖/二审/选项页）已交付。P2 补齐处置动作（词汇表承诺的折叠/过滤）、扩展覆盖面（专栏文章页）、解锁非 DeepSeek 用户（动态 API 域名）、提供汇总与导出。

## 2. 任务总览

| # | 任务 | 来源 | 优先级 |
|---|---|---|---|
| 01 | 处置动作：折叠 / 过滤 | CONTEXT.md"折叠/过滤为后续迭代" | 高 |

## 3. 各任务定义与验收

### 01 处置动作：折叠 / 过滤

- 选项页新增"处置动作"配置：标记（MVP 现状）/ 折叠 / 过滤，可按等级分别配置
- 折叠：判定为确定/疑似 AI 的回答自动收起正文，保留角标，可一键展开
- 过滤：判定为确定/疑似 AI 的回答从列表中隐藏，显示"已过滤 N 条"提示条，可恢复
- 验收：热榜页配置折叠后，低分回答正文收起；过滤后列表变短且提示条可恢复；覆盖为"认为人工"的回答不受处置动作影响
- 风险：知乎 SPA 重渲染可能重建卡片 → 处置动作需在重渲染后重新应用（复用 MutationObserver 流程）

### 02 专栏文章页支持

- manifest 增加 `https://*.zhihu.com/zhuanlan/*` 与 `https://*.zhihu.com/p/*` matches（评估是否需要单独 content script）
- 正文来源 `.Post-RichText`（research 已记录）；文章无"回答 ID"，覆盖/缓存键改用内容哈希或文章 URL
- 验收：打开专栏文章页出现判定角标与理由面板；覆盖/缓存按文章维度生效

### 03 自定义 API 域名动态权限

- manifest 声明 `optional_host_permissions: ["https://*/*"]`（或按用户输入精确域名）
- 选项页保存自定义 base URL 时，经 SW 触发 `chrome.permissions.request`（注意 skill 规则：SW onMessage 中 request 必须在用户手势的同一同步轮次内调用，无 await 前置）
- 验收：把 base URL 改为任意 https 域名 → 弹出权限申请 → 授权后二审可用；拒绝则提示并回退本地规则

### 04 本页判定统计面板

- 页面注入轻量汇总条：已判 N / 确定 AI / 疑似 AI / 跳过 计数，随分析实时更新
- 数据来自内容脚本 state.results，无需新存储
- 验收：滚动加载后计数正确；与页面实际角标数一致

### 05 判定/覆盖数据导出

- 选项页"导出"按钮：将覆盖记录 + 二审缓存（或本页判定结果）导出为 JSON 下载
- 验收：导出文件包含回答 ID/内容哈希、分数、来源、时间；可再导入？（导入不做，仅导出）

## 4. 依赖与约束

- 01、04 无外部依赖，复用 MVP 的判定管线与 DOM 注入
- 02 需在 extract 模块扩展选择器（保持单点维护约定）
- 03 涉及权限模型变更，需更新 CHROMEWEBSTORE.md 权限说明
- 所有任务完成后需回归 MVP 功能（覆盖/二审/缓存不受影响）

## 5. 明确不做（P3+）

- 盐选内容/登录墙全文展开（依赖登录态，评估后再定）
- 本地模型检测（ADR-0002 已排除，除非硬件/模型条件变化）
- 覆盖/导出数据云同步
