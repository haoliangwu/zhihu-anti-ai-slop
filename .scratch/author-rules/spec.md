# 知乎照妖镜 — 作者控制 Spec

> Status: ready-for-agent · 关联: `.scratch/mvp/spec.md`、`.scratch/p2/spec.md`、`CONTEXT.md`、ADR-0001/0002

## 1. 背景

现有判定管线只认 `answerId`（卡片级），完全不存在作者概念。用户提出"拉黑功能变种"：**固定屏蔽某个作者**（不在乎是否人工）与**始终显示某个作者**（不在乎是否 AI）。经 /grill-me 逐轮拷问确认设计（见 §3 决策记录）。

## 3. 已确认的设计决策（grill 轮次）

- **屏蔽实现**：纯本地隐藏（不模拟点击知乎拉黑按钮），占位条可恢复
- **信任语义**：一轮也不跑——一审规则、二审、角标全部跳过；屏蔽同理直接隐藏，二者都不再走提取/判定
- **两个方向都做**，同一数据结构的对称行为
- **身份识别**：`zhihu.com/people/<token>` 主键（稳定），昵称仅显示；**匿名回答无作者链接，不可屏蔽/信任**（仅走卡片覆盖）
- **优先级**：作者级规则 > 卡片级覆盖 > 引擎判定（硬规则）
- **自己回答的保护**：暂缓（需调研知乎 API 如何标识当前用户身份，用户提示知乎支持 API 调用）
- **管理入口**：① 角标面板「屏蔽该作者」「信任该作者」按钮（匿名卡不显示）；② 选项页「作者管理」section
- **信任卡呈现**：极低调灰色小签「已信任」（点击 → 取消信任/屏蔽该作者），与屏蔽卡占位条对称可反悔
- **即时生效**：屏蔽/信任后重扫本页该作者全部卡片（含已分析的）

## 4. 依赖与约束

- 01 是完整纵切片（提取 → 数据层 → 核心流程 → 卡片 UI），具备演示性，先做
- 02 复用 01 的存储层与内容脚本监听，仅加选项页 UI
- 03 含回归清单：覆盖、二审（缓存/重判定）、隐藏正文、首页时间线判定不受影响
- 完成顺序：01 → 02 → 03，然后才允许 `.scratch/articles/` 开工（用户明确要求严格顺序）

## 5. 明确不做

- 真实知乎拉黑（模拟点击平台按钮）
- 自己回答的保护（待 API 调研，进 backlog）
- 评论/想法（Pin）内容的作者规则
