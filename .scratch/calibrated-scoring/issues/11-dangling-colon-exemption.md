# 11 — 图文穿插回答的段尾孤悬冒号 + 连接词名词义误判（一审 22 分）

Type: bug
Status: done
Priority: P1

**发现途径：** 用户 100% 手写回答（https://www.zhihu.com/question/2076658278310885259/answer/2077362280732308875，2026-08-30 上午）一审被判 22 分「确定 AI」，本地复现与页面角标完全一致（角标 22(48) 疑似 AI 二审）。

## 根因（本地逐特征消融 + 全语料实证）

1. **段尾孤悬冒号（主因，−2.33 logits）**：正文是"每段 prompt / 结果 → 配图"的排版，11 个全角冒号中 10 个在段尾（`prompt 如下：`、`数据如下：`、`1m 12s：`…），冒号指向的对象是被 `NON_PROSE_SELECTOR` 剔除的 `figure`。提取层剔除图片后，文字流里只剩一串孤悬冒号。校准模式按原始命中数线性累加（`contribution = count × w`，w = −0.2116/个，cap 仅旧扣分制使用）⇒ −2.33 logits。
   - 全语料分布（段尾孤悬冒号 = 冒号后紧跟换行/文末）：人类 1.7%（50/2956）、flash 7.1%（210/2956）、旧 AI 0.02%（4/26115）。flash 侧该模式确实略多，但图文类人类回答（技术测评）天然就是这种写法——单个冒号的判别力来自"引出解释/定义"的行内用法，段尾孤悬冒号是训练时混入的噪声因素。
   - **连带伤害**：统计特征 `punctDensity`（权重 −18.44/单位）被 11 个冒号推高到 0.0792 ⇒ −1.46 logits。词法 + 统计合计 ≈ −3.8 logits，占从 74 拉到 22 的下拉量 ~90%。
2. **连接词骨架（次因，2/3 假阳性）**：「价格**其次**」（名词义）、「**是最后**，花了将近 4m」（形容词义）被 `其次|第二，` 全文本匹配计分；且两个假阳性各自让"最后仅成链时计分"的链条条件（hasFirst/hasMid）成立，互相成链触发。真命中仅「综上所述」1 处。

## 修复（A + C，用户确认）

- **A（提取层，`src/content/extract.js` `paragraphsOf` 两条路径）**：段落 trim 后剔除段尾全角冒号 `：+$`——图片/嵌入内容被剔除后不留 DOM 残渣进特征计数（与 issue 04 `NON_PROSE_SELECTOR` 同一原则）。词法 `colon-overuse` 与统计 `punctDensity` 因此天然一致地看到干净文本，双豁免。
- **C（`src/engine/traces.js` `connector-skeleton`）**：`其次|第二，` 仅**句首连接词义**计数（前接句末标点/换行/文首：`(^|[。！？!?\n；;])`），排除名词义（"价格其次"）与排名义（"是第二，"）；`最后` 的成链条件沿用（hasFirst/hasMid），因 hasMid 收紧而不再被名词义误链触发。

## 边界情况（已知，接受）

- 训练分布内的段尾孤悬冒号（人类 1.7%）也被豁免——实测全语料人类误报几乎不变（4.9%→4.8%），换取图文排版类手写回答不再误伤，净收益为正。
- `maxChars` 截断发生在 join 之后，极端情况下截断点恰在冒号后会产生新的人工孤悬冒号——罕见，单个冒号贡献有界（≤0.21 logits），接受。
