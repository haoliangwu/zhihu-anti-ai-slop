# 04 — 代码块混入打分窗口导致误判（正文提取剔除 pre）

Type: bug
Status: done
Priority: P1

**发现途径：** 用户自写回答（https://www.zhihu.com/question/2076311522641449389/answer/2076624850437796291）被判 0 分「确定 AI」，内容 100% 手写。

## 根因

1. 正文提取 `BODY_BLOCK_SELECTOR` 包含 `pre`（代码块），整段代码/配置原样进入打分窗口；
2. 特征 `straight-quote（英文双引号标注）` 对代码内 ASCII 引号计数：JSON preset 配置命中 **73 次**；
3. 校准模式按原始命中数线性累加（`contribution = count × weight`，权重 −0.195/次，cap 仅旧扣分制使用）→ 贡献 −14.24；
4. logit = 截距 0.722 − 0.558（句长齐整）+ 1.541（冒号滥用）− 14.242 ≈ −12.5 → σ ≈ 0 → 0 分。

**本质：** 模型权重在纯正文语料（C-ReD）上拟合，训练分布内几乎没有「回答内嵌代码块」样本；线性外推在超大命中数下必然爆分。代码不是写作痕迹，任何写作特征都不应在代码上计数。

## 修复（两次迭代）

**v1（单点）：** `BODY_BLOCK_SELECTOR` 移除 `pre` → `'p, li, blockquote, h1, h2, h3, h4, h5, h6'`。

**v2（通用化）：** 新增 `NON_PROSE_SELECTOR` + `proseTextOf()`——「非散文内容一律不参与特征计数」：
- 块级：`pre` 不在 BODY_BLOCK_SELECTOR（整体跳过）；代码容器内的块级元素（如 pre 里的 li）经 `closest(NON_PROSE)` 过滤；
- 行内：每个正文块克隆后剔除代码/嵌入元素（`code, kbd, samp, tt, math, .ztext-math, figure, figcaption, video, audio, iframe, embed, object, canvas, template, .ztext-video`）再取文本，行内代码片段不再污染特征；
- 兜底路径（无块级正文时整段切分）同样剔除。

连带收益：代码内的英文冒号、整齐短行（句长齐整）也不再误触发。

**教训（v2 踩坑）：** 勿用泛化的 `[class*="..."]` 猜测非散文——知乎划词高亮 `.highlight-wrap`（评论高亮）包裹的仍是作者正文，曾被误剔除导致佳人李大花回答 75 → 63（句长齐整误触发）；已移除该选择器并回验 75。只匹配标签与知乎专用类。

**验收（浏览器实测，扩展重载 + 页面刷新）：**

- [x] 用户回答：`0 确定 AI 3 条痕迹` → `91 正常 1 条痕迹`（命中仅冒号滥用 ×6 +1.54；logit = 0.722 + 1.541 = 2.263 → σ = 0.906 → 91）
- [x] 二审缓存：正文哈希变化自动失效重判；91 分不在模糊带 [30,50]，不消耗云端调用
- [x] 问题页全量回归：佳人李大花 75、螺旋真理 58、夏夏回来了 72、王昊诚 50(67) 二审、夏庆 52——与修复前一致
- [x] 行内代码/划词高亮共存场景：仅剔除非散文，`.highlight-wrap` 正文保留

## 边界情况（已知，接受）

- 纯代码无散文的回答字数变少，低于字数下限（回答 300）显示「跳过」——合理，纯代码无法按写作特征判定。
- 校准模式计数未加 cap（与训练语义一致：`x_i = cap 前命中数`）。若后续要对极端命中数做截断（winsorize），需训练与推理同步改并重拟合，不在本次范围。
