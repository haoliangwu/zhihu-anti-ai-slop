> Status: ready-for-agent · 关联: `.scratch/research/statistical-scoring-feasibility.md`、`.scratch/mvp/spec.md`、`CONTEXT.md`、ADR-0001/0002
> 最近更新：方案 A 立项（用户确认「先做 A，先建票」，B/C 明确不做）

## 1. 背景

当前一审（`src/engine/rules.js` + `traces.js`）是固定句式正则的**加性扣分制**：`score = 100 − Σ min(count, cap)×weight`，权重为手拍整数，分数不是概率、无置信度语义，且固定句式可被改写绕过、对正式/文学文体易误伤。用户质疑其公平性。

调研结论（`.scratch/research/statistical-scoring-feasibility.md`）：把现有 ~20 条内置痕迹的**命中数作为特征向量**，用逻辑回归拟合校准权重，输出 `P(人类)×100`——纯 JS 客户端可行（运行时仅 sigmoid+点积），标注数据现成（C-ReD 含知乎 KOL 问答 + 多 LLM 生成，与目标域几乎同构），且有中文问答先例（HC3 用「特征+逻辑回归」验证过该路线）。现扣分制本质就是未校准的线性模型，方案 A 是其校准化推广。

## 3. 已确认的设计决策

- **模型**：逻辑回归 `logit p = w·x + b`；`x` = 内置 ~20 条痕迹在 cap 前的命中数向量；`p` = 人类概率
- **分数语义**：`score = round(p × 100)`，仍为「人类置信度」（ADR-0001 不变）
- **阈值与模糊带（用户确认随模型数据落地，修订自"全部复用"）**：校准后分数分布整体下移（人类中位 67 分），旧默认 40/70/[20,80] 与校准尺度不兼容（会误标 66% 人类、云端触发率 84%）。新默认：**确定 ≤30**（人类误报 3.7%）、**疑似 ≤50**（Youden J：AI 检出 60%/人类误报 11%）、**模糊带 [30,50]**（= 疑似区，云端只处理真正模糊的区间，控制调用成本）；选项页默认值更新、用户仍可编辑
- **二审加权融合**（0.6·cloud + 0.4·rule）复用不变
- **可解释性**：命中清单保留，理由面板升级为**逐特征对数几率贡献**（`w_i·x_i`，带符号：正=偏向人类，负=偏向 AI，保留两位）+ 命中次数 + 语义说明行；二审上下文同步改为带符号贡献
- **用户自定义正则**：不进学习权重；保留原扣分语义，在 sigmoid 结果上按原 deduct 扣减并钳制 0–100（用户显式规则 = 强信号，语义不稀释）
- **符号翻转特征（用户确认数据驱动原样交付）**：冒号/句号当顿号/伪口语/伪亲密等 9 个特征在本域拟合为人类信号，保留；4 个符号不稳的噪声特征（元评论/励志结尾/成语堆砌/死隐喻，|w|≤0.09）置零
- **回退开关**：代码级常量（默认启用校准；切回后与现版行为完全一致），不在选项页暴露
- **权重来源**：01 离线拟合产出常量表 + 截距，写入 `src/engine/calibrated-weights.js`，文件内注明拟合数据/日期/样本量
- **01 门槛**：留出集上 Accuracy / AUROC / Brier 三项中，**AUROC 或 Brier 至少一项优于现扣分制**，否则 02 不开工、结论写回调研文档

## 4. 依赖与约束

- 01 需要公开数据集：优先 C-ReD Q&A 子集（知乎 KOL 人类 + 多 LLM 生成，含 DeepSeek）；不可用则 HC3 中文问答；两者均不可获取 → 01 标记 blocked 并回报，**不自行造数据**
- 01 的特征提取必须与扩展实际正则**单一事实源**：Node 端直接加载 `src/engine/traces.js` 复算命中数，不允许另写一份正则
- 02 不改变：消息协议、存储格式、二审缓存键（缓存键含一审摘要；一审分变化 → 摘要变化 → 自动重判，无需数据迁移）
- 完成顺序：01 → 02 → 03（01 是硬前置）
